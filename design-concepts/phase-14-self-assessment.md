# Phase 14 — Самооценка дизайнера + подтверждения

> План согласован с Pavel 11.07.2026 (роли: product-manager + product-designer).
> Решения по развилкам: **только ссылки** (без загрузки файлов) · **окно всегда
> открыто** · **видимость — все стороны** (дизайнер видит расхождения с лидом
> после публикации).

## 1. Зачем (JTBD)

- **Дизайнер:** «Когда я расту между сезонами, помоги мне зафиксировать, чем
  я владею и чем это подтверждено, — чтобы на грейдировании не вспоминать
  полгода работы за один вечер».
- **Лид:** «Когда я грейдирую 5–7 человек за сезон, помоги мне видеть
  самооценку и материалы дизайнера рядом с каждым навыком — чтобы ставить
  уровень по фактам, а не по памяти, и быстрее».
- **Pavel (админ):** «Покажи, где команда себя переоценивает/недооценивает —
  это темы для 1:1 и сигнал о калибровке шкалы».

**Принцип-гардрейл:** самооценка — референс для лида. Она НЕ участвует в
расчёте XP/грейда и не влияет на composite. Только подсветка.

## 2. Scope

### MVP (берём)
1. **Самооценка уровня** по каждому навыку: дизайнер отмечает свой уровень
   на существующей лестнице уровней мастерства в аккордеоне навыка
   (портрет), + необязательный комментарий. Одна запись на (дизайнер, навык),
   меняется в любой момент, хранится дата обновления.
2. **Подтверждения-ссылки**: список ссылок (Figma/Notion/Drive/Loom/любой URL)
   с названием и опциональным описанием, привязан к (дизайнер, навык).
   Добавление/удаление — только владельцем.
3. **Форма оценки (лид):** рядом с каждым навыком — чип «Сам: N» и дата
   обновления самооценки; при расхождении с выбором лида чип подсвечивается
   (выше — sunset, ниже — sky). Ссылки-подтверждения — раскрываемый список
   под навыком.
4. **Портрет после публикации:** в аккордеоне навыка на лестнице уровней две
   метки — уровень лида (заливка, как сейчас) и самооценка (контурная метка
   «Я»); строка-агрегат в шапке разбора: «Расхождения: N навыков».

### Не берём сейчас (Later)
- Загрузка файлов (S3/volume) — отменено выбором Pavel.
- Напоминания «обнови самооценку перед сезоном» (кандидат в фазу
  уведомлений).
- Аналитика расхождений по команде (heat-view для Pavel) — после того как
  наберётся первый сезон данных.
- Обязательность подтверждений для высоких уровней.

## 3. Модель данных (prisma db push)

```prisma
model SelfAssessment {
  id         Int      @id @default(autoincrement())
  designerId Int
  designer   User     @relation(fields: [designerId], references: [id])
  skillId    Int
  skill      Skill    @relation(fields: [skillId], references: [id])
  level      Int      // 1..maxMasteryLevel
  comment    String?
  updatedAt  DateTime @updatedAt
  createdAt  DateTime @default(now())

  @@unique([designerId, skillId])
  @@map("self_assessments")
}

model SkillEvidence {
  id          Int      @id @default(autoincrement())
  designerId  Int
  designer    User     @relation(fields: [designerId], references: [id])
  skillId     Int
  skill       Skill    @relation(fields: [skillId], references: [id])
  url         String
  title       String
  description String?
  createdAt   DateTime @default(now())

  @@index([designerId, skillId])
  @@map("skill_evidences")
}
```

## 4. API

- `GET /api/users/[id]/self-assessment` — все самооценки+evidence дизайнера
  (читают: сам, его лид/стардиз, админ).
- `PUT /api/users/[id]/self-assessment/[skillId]` — upsert уровня+комментария
  (пишет только владелец; level ≤ maxMasteryLevel навыка).
- `DELETE` того же — снять самооценку.
- `POST /api/users/[id]/skill-evidence` / `DELETE /api/skill-evidence/[id]`
  (только владелец; валидация URL http/https; лимит 20 ссылок на навык).
- Форма оценки (`/lead/assess`) получает самооценки серверно вместе со
  скиллами — без клиентских дозапросов.
- Аудит: `self_assessment_updated`, `evidence_added/removed` НЕ логируем
  (личный инструмент, шум); решение можно пересмотреть.

## 5. UX (ключевые экраны)

### Портрет, аккордеон навыка (владелец)
- Существующая лестница уровней получает интерактив для владельца:
  клик по уровню = «я владею до этого уровня» (метка «Я» садится на уровень,
  glass-чип). Повторный клик — снять. Рядом поле комментария (inline,
  автосейв on blur).
- Ниже — секция «Мои подтверждения»: строки «favicon-тип · title → url ·
  дата · ×». Кнопка «+ ссылка» разворачивает inline-форму (url, title,
  описание). Пустое состояние — EmptyState-мини с подсказкой.
- В шапке разбора навыков — тихий прогресс «Самооценка: 34 из 51» (stone),
  мотивирует добить.

### Форма оценки (лид)
- Под заголовком навыка чип `Сам: Уровень 3 · май 2026` (glass). Если
  текущий выбор лида ≠ самооценке: чип тонируется (самооценка выше выбора —
  sunset «переоценка?», ниже — sky «скромничает?»). Без агрессии: тон, не
  крик.
- «Подтверждения (N)» — раскрываемый список ссылок под критериями уровня,
  открываются в новой вкладке.

### Портрет после публикации (все, кто видит портрет)
- На лестнице уровня две метки: заливка = оценка лида, контур «Я» =
  самооценка. Легенда в шапке разбора.
- Строка-агрегат: «Расхождения с самооценкой: 6 навыков» (клик — фильтр
  разбора по расхождениям) — MVP: без фильтра, просто число.

## 6. Метрики успеха (проверяем через сезон)
- ≥70% активных дизайнеров имеют самооценку по ≥50% навыков к началу сезона.
- Лиды отмечают ускорение грейдирования (опрос после сезона; сейчас форма
  занимает вечер на человека).
- Доля навыков с расхождением ≥2 уровней < 15% (иначе шкала уровней требует
  калибровки — сигнал для Pavel).

## 7. Риски
- **Инфляция самооценки** → гардрейл: не влияет на расчёт, расхождения
  прозрачны обеим сторонам — социальный контроль.
- **51 навык = усталость** → интеракция в 1 клик на навык, прогресс-счётчик,
  без обязательности.
- **Протухшие ссылки** → показываем дату добавления; чистка — вручную.
- **Обиды на расхождения** → тон подсветки нейтральный, формулировки без
  оценочности; расхождение = повод для 1:1, так и подаём в UI-копирайте.

## 8. Порядок работ (4 шага ≈ 4 сессии)
1. Модель + API + права (db push, unit-логика прав как в checklistPermissions).
2. Портрет владельца: интерактивная лестница + «Мои подтверждения».
3. Форма оценки лида: чипы самооценки + подсветка расхождений + ссылки.
4. Портрет после публикации (две метки, агрегат) + полировка + аудит-решение.
