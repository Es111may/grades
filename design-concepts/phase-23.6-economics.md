## 2. Показатели — определения как в табличке

Период — **с 1 января текущего года** (как «С начала года» в поп-апе и формулы
листа «Дэшборд 2026»). Сравнение — с тем же днём прошлого года (YoY).

| Показатель | Формула | Где показываем |
|---|---|---|
| ФОТ / мес | Σ текущих ставок активных | Шапка, график, по уровням |
| Человек | Число активных | Шапка, график, по уровням |
| МЗП | Медиана текущих ставок | Шапка, по уровням |
| СЗП | Среднее текущих ставок | Только внутри ФОТ и в подсказке — среднее искажается одним лидом |
| ССЗП (цена найма) | Среднее стартовой ставки нанятых с 1 января | По уровням, блок «Найм и уходы» |
| ГПЗП | Σ (текущая ставка − ставка на 1 января) по людям с ростом > 0 | Блок «Куда ушли деньги» |
| CГПЗП | ГПЗП / число людей с ростом | Там же |
| Доля в ФОТ компании | ФОТ дизайна / ФОТ компании (`stats_wagefundstats`) | Шапка, график |
| Отток | Уходы за 12 мес / средняя численность; сравнение с компанией (`stats_monthlyemployeestats`) | Блок «Найм и уходы» |

YoY показываем только у общих цифр: на группах в 1–5 человек он шумит.
Малые группы: медиана показывается, но с подписью «n = 2».

- **Шапка (bento):** четыре карточки как на «Команде»: число 44 px, YoY, на
  ФОТ — полоса прогресса к цели года.
- **«Куда ушли деньги»:** горизонтальное разложение (было → +повышения →
  +наймы → −уходы → стало), под ним ГПЗП и CГПЗП и строка цели: «Цель на год
  +10% · сейчас +N% · запланировано пересмотров +X» (из плановых пересмотров).
- **«По уровням»:** таблица; ставки — точками на шкале вилки (тот же визуальный
  язык, что BandMeter в поп-апе); «Вне вилки» — выше/ниже с цветом как в
  поп-апе; «Найм» — ССЗП за год. Клик по уровню — список людей уровня.
- **«Динамика»:** график ФОТ и численности по месяцам; доля в ФОТ компании —
  вторая тонкая линия.
- **«Найм и уходы»:** цифры за 12 мес, отток против компании, ~8 групп причин
  с инициатором; «▸» раскрывает людей группы (имя, дата, причина, куда ушёл),
  «Все причины» — полный список подкатегорий.
- **Фильтры:** «Отдел» и «Направление» на общем `FilterDropdown`; применяются
  ко всей странице. Отдельных таблиц по отделам и направлениям нет.
- **Переключатель «На руки · Для компании»:** сегмент справа в ряду фильтров,
  меняет все суммы страницы; коэффициент (×1,36) — в подсказке и в настройках.
  По умолчанию «На руки» (как в HR). Выбор запоминается в браузере.
- **⚙ Настройки** (поп-ап): цель роста ФОТ в год (10%), налоговый коэффициент
  (36%), потолок ставки (пусто = не используется). Хранение — `Setting`
  key-value, правка — только админ, запись в «Действия».
- **Состояния:** HR недоступен — последние посчитанные цифры с меткой «Данные
  от …»; неполная история ставок — подпись «История ставок есть по N из M».

## 4. Реестр: 122 человека в «Команде»

- **Импорт из HR** (разовый скрипт вне репозитория + повторяемая сверка):
  нынешние совпадают с пользователями Грейдов по email; ушедшие создаются как
  `User` с `active = false`, без пароля (войти нельзя), `hiredAt` и
  `dismissedAt` из HR, тип и причина ухода — из таблички (как перенос 30.09).
  `ExcludedEmail` уважаем: исключённых не создаём, список — в отчёте.
- **Направление (`track`)**: дизайн / БА·СА / UX-редактор / исследователь —
  из позиции HR, с ручным переопределением. Не-дизайн не грейдируется (как
  почасовщик) и не входит в рейтинг.
- **«Текущие / Все»** — сегмент в ряду фильтров «Команды», по умолчанию
  «Текущие». В «Все» неактивные — серыми строками внизу, как сейчас.
- **Неактивная карточка (поп-ап):** «Команда» (лид на момент ухода, если
  есть), даты найма и увольнения, статус (админ); «Зарплата» (админ — последняя
  ставка и история из HR); «Грейдирование» — оценки, если были. Действий
  оценки и пересмотра нет.
- **Проверить по всему коду:** счётчики, выпадающие списки лидов/стардизов,
  NIPC, 9-Box, «Требует внимания», лидерборд, «Функционал» — неактивные не
  должны попадать туда, где их раньше не было.

## 5. Данные и производительность

- Источник — HR (ClickHouse): `employee_employee`, `salary_changesalarylog`,
  `stats_wagefundstats`, `stats_monthlyemployeestats`, справочники причин.
- Помесячный ряд: ставка каждого человека на конец месяца — из журнала; у
  кого журнала нет — текущая ставка (приближение) с пометкой покрытия.
- Расчёт — чистые функции в `lib/economics.ts` с тестами на выдуманных данных;
  выборка — один батч-запрос, кэш `perfCache` (stale-while-revalidate),
  бюджет ожидания 8 с, как на «Команде».
- Суммы не уходят никому, кроме админа: страница и API режут на сервере.

## 7. Риски

1. **85+ неактивных пользователей** расползутся по спискам, если где-то
   фильтр по `active` забыт — нужен аудит (п. 4).
2. **Неполная история ставок** в HR — «год назад» и разложение неточны до
   23.5; честно показываем покрытие.
3. **Чувствительность:** зарплаты всей истории + причины ухода — только админ,
   серверная фильтрация, ничего в git (импорт — скриптом вне репо).
4. **ClickHouse по http** — сводные цифры идут тем же каналом (отложено).
