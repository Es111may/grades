# План разработки веб-сервиса грейдирования дизайнеров

**Версия:** v1.0 (MVP)
**Контекст:** Standalone веб-приложение, разработка solo (Pavel + AI), внутренний хостинг + корп. SSO, 20–50 дизайнеров / 3–7 лидов.

---

## 1. Что делаем (scope MVP) и чего НЕ делаем

### Делаем
1. **Авторизация** через корп. SSO с тремя ролями: Admin, Lead, Designer.
2. **CRUD дизайнеров**: добавить, редактировать профиль (ФИО, e-mail, билд, текущий грейд, отдел, дата найма).
3. **Ввод оценок лидом**: форма проставления Мастерства (0…N) по каждому навыку. Сохранение черновиков, история изменений.
4. **Расчёт XP и грейда**: автоматически из мастерства × вес (по билду), сравнение с порогом XP и проверка обязательных навыков-гейтов.
5. **Портрет дизайнера**: блок "освоенные навыки", сводка XP по 5 скиллам, итоговый грейд, листовая (radar) диаграмма "текущий vs MAX в рамках уровня".
6. **Шаринг**: дизайнер заходит в свою учётку и видит свой портрет (read-only).
7. **Админ-интерфейс матрицы компетенций**: возможность редактировать веса, мастерство-уровни, гейты без релиза кода.

### НЕ делаем (вырезано из MVP осознанно)
- Самооценка дизайнером + загрузка фигма-файлов как доказательств (план 7).
- Иконки навыков и кастомная визуализация (план 8).
- ИПР с уровня Мидл (план 3 из листа "Планы на грейды").
- Интеграция с Tims / другими HR-системами (план 9).
- Mobile-приложение, push-уведомления.

**Почему:** каждый из этих пунктов в одиночку = +2–4 недели. Отрезаем — собираем работающий каркас, дальше итерируем.

## 2. Архитектура

### Стек (рациональный выбор для solo+AI)
| Слой | Технология | Обоснование |
|------|-----------|-------------|
| Frontend | **Next.js 14 (App Router) + TypeScript + Tailwind** | AI хорошо генерит этот стек, серверные компоненты упрощают SSR, не нужен отдельный API-сервер. |
| Charts | **Recharts** | Радар-диаграмма "из коробки", не нужно писать руками SVG. |
| Backend | Next.js API Routes (на одном с фронтом сервере) | Один деплой, один репозиторий. Не плодим микросервисы для команды на 50 человек. |
| БД | **PostgreSQL** + Prisma ORM | На вырост. SQLite соблазнителен, но миграции на PG потом — это боль. |
| Auth | **NextAuth.js** + корп. провайдер (Keycloak / Yandex / Azure AD) | NextAuth поддерживает любой OIDC-провайдер. До интеграции с корп. SSO — заглушка через email/magic-link. |
| Хостинг | Внутренний сервер (Docker-compose: app + Postgres) | Или внутренний Kubernetes, если есть. |
| Версионирование | Git + GitHub/GitLab | Стандарт. |

**Альтернатива (если Next.js не зайдёт):** FastAPI (Python) + React/Vite + Postgres. Чуть больше boilerplate, но ты почти не пишешь сервер сам — просит AI.

### Не рекомендую (и почему)
- **Не SQLite** — переезд под нагрузку = миграция данных = риск порчи оценок.
- **Не два разных приложения (фронт+бэк отдельно)** — solo-разработчику это удвоение деплоя.
- **Не серверные шаблоны (Django/Rails)** — графики и интерактив всё равно потребуют JS-фронта.

## 3. Модель данных (ключевая часть)

> **Главный принцип:** матрица компетенций — это **данные в БД**, а не код. Иначе любая правка веса = релиз. Это самый частый провал HR-tools.

### Таблицы

```
skills_taxonomy
  id, code (UI/UX/PRD/IND/RES), name, sort_order

skill_groups
  id, taxonomy_id, name, sort_order

skills
  id, group_id, name, description (italic),
  type (CORE/SEC), max_mastery_level,
  confirmation_criteria (text per level), proof_examples (text)

builds
  id, code (visioner/navigator/creator), name, description

skill_weights
  skill_id, build_id, weight  -- (3 строки на навык)

mastery_levels
  skill_id, level (1..N), title, description, criteria

grade_levels
  id, code (junior/junior_plus/middle/middle_plus/senior),
  sort, xp_threshold (per build via jsonb)

skill_gates
  grade_level_id, build_id, skill_id, required_mastery_level
  (антифарм: чтобы получить уровень — обязательно эти ноды)

users
  id, email, full_name, role (admin/lead/designer),
  build_id, department, lead_id (FK на user), hired_at, sso_id

assessments
  id, designer_id, lead_id, status (draft/published),
  created_at, published_at, version

assessment_scores
  assessment_id, skill_id, mastery_level (0..N), comment, evidence_url

assessment_history (audit log)
  assessment_id, changed_by, changed_at, diff (jsonb)
```

### Логика расчёта (хранимая в коде, не в БД)
1. Для каждого навыка: `xp = mastery_level × weight[build]`.
2. Сумма XP по 5 скиллам = total_xp.
3. Проверка гейтов:
   - Total XP ≥ порог уровня?
   - Все required_skills закрыты на нужном уровне мастерства?
   - **Если оба условия выполнены → этот уровень доступен. Иначе — текущий уровень фиксируется на максимально достижимом.**
4. Логирование каждого изменения для аудита.

### Импорт исходных данных
Перед стартом — скрипт-импортёр, который **читает Excel-шаблон 2.0 и заливает в БД**. Это снимает риск ручного ввода 50 навыков × 3 веса × 5 уровней мастерства.

## 4. Этапы (фазы)

| Фаза | Длительность | Результат |
|------|--------------|-----------|
| **0. Дизайн данных** | 3–5 дней | Финализирована модель данных, скрипт импорта Excel→БД работает на копии шаблона. |
| **1. Каркас + Auth** | 3–4 дня | Next.js + Postgres + NextAuth (заглушка), базовый layout, ролевая модель. |
| **2. Управление пользователями** | 2–3 дня | CRUD дизайнеров, привязка билда и лида. |
| **3. Форма оценки** | 5–7 дней | Главный экран лида: выбираешь дизайнера → видишь все навыки → проставляешь мастерство → видишь авто-расчёт XP в реальном времени. Черновик/публикация. |
| **4. Портрет дизайнера** | 4–5 дней | Страница "мой портрет": сводка XP, освоенные навыки, грейд, листовая (radar) диаграмма. |
| **5. Админ-панель матрицы** | 3–4 дня | Редактирование весов, гейтов, уровней мастерства без релиза. |
| **6. Корп. SSO** | 2–4 дня | Подключение реального IdP. |
| **7. Тестирование на 2 дизайнерах** | 2–3 дня | Сверка с ручным расчётом из Excel. Момент истины. |
| **8. Деплой + документация** | 1–2 дня | Docker-compose, инструкция, бэкапы. |

**Итого:** 25–37 рабочих дней (5–7 недель чистого времени). Реально с учётом твоих основных задач — **2,5–3 месяца до прод-запуска.**

## 5. Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Лиды не будут заполнять оценку (50 полей — много) | **Высокая** | Группировка по 5 скиллам с прогресс-баром, авто-сохранение черновика, можно заполнять частями. UX-дизайн формы важнее, чем UX портрета. |
| Матрица меняется каждые 2–3 месяца | **Высокая** | Матрица — данные. Версионирование матрицы (snapshot на каждую оценку), чтобы старые оценки не "развалились" при правке весов. |
| Корп. SSO не интегрируется | Средняя | На MVP — magic-link через корп. SMTP. Параллельно — заявка в IT. |
| Несогласие дизайнеров с оценкой | Средняя | Поле "комментарий" к каждому навыку, история версий, дата публикации, возможность пересмотра. |
| Расчёт XP в коде разойдётся с Excel | Средняя | Параллельный прогон фазы 7 — 2–3 реальных профиля из Excel, сверка по каждому числу. |
| Боязнь "холодного запуска" | Средняя | Запуск на 1 отделе → обратка → доработка → расширение. |
| Скрытая мотивация лидов "помочь" любимым дизайнерам | **Высокая** | Аудит-лог изменений + видимость руководителю отдела статистики выставленных оценок (есть ли у Лида X систематическое завышение). |

## 6. Что нужно от тебя ДО старта

1. Согласовать модель данных — чтобы не переписывать БД на 3-й неделе.
2. Получить от IT: имя/тип корп. IdP, требования к хостингу, выделенный сервер.
3. Согласовать с командой матрицу — зафиксировать v1.
4. Собрать e-mail'ы дизайнеров и лидов + матрицу "кто чей лид".
5. Прогнать концепцию вручную в Excel на 2–3 дизайнерах ДО старта разработки.
6. Решить про двухступенчатую публикацию (лид заполняет → руководитель апрувит → видит дизайнер) или одноступенчатую.

---

## 7. Что предлагаю первым шагом

**Не лезть в код.** Сначала собрать **техническое задание (PRD)** на 4–6 страниц с экранными мокапами и схемой БД. Это:
- даст тебе чёткое понимание объёма работы;
- послужит ТЗ для AI-кодера — без него генерация кода превратится в хаос;
- позволит параллельно согласовывать с IT.

**Следующие шаги, если согласен с планом:**
1. Подготовлю PRD-документ.
2. Сделаю HTML-мокапы основных экранов (форма оценки, портрет, админка матрицы).
3. Подготовлю репозиторий с базовой структурой Next.js + Prisma + миграциями.
